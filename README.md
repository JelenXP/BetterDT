# BetterDT – mods for Devices Tycoon

[![Discord](https://img.shields.io/badge/Discord-join%20us-5865F2?logo=discord&logoColor=white)](https://discord.gg/JdQEMNNTrN)

Handy extra buttons for **Devices Tycoon** that save you a lot of clicking. BetterDT does not change any
game file and does not touch your saves.

**Discord:** [discord.gg/JdQEMNNTrN](https://discord.gg/JdQEMNNTrN) – questions, ideas and bug reports.

## What you get

- **Hiring (FIND EMPLOYEES):** a second button next to every agency keeps searching until your office is
  full. With **AUTO-HIRE** (checkbox in the top right) everyone found is hired right away.
- **Training (UPGRADE EMPLOYEES):** the game's button says which profession it upgrades (**UPGRADE DESIGNERS**:
  one step for everyone), and **ALL TO MAX** under it trains everyone of all professions to the maximum level, as
  long as you have money and research points (it shows about how many points and how much money that takes).
- **Research (RESEARCH LAB):** next to the game's own button (renamed **Research tab**: the tab you have open,
  recommended functions first, at most half of your money) **Research all** researches everything on all tabs, for
  research points and money. It is greyed out when you cannot afford all of it; hovering it shows the price, and a
  click first asks with the price.
- **Game speed ×2 and ×3:** the speed button in the corner goes ×1 → ×1.25 → ×1.5 → ×2 → ×3.
- **Adjustable autosave:** the game's Autosave setting (30 to 365 days) becomes a slider from 5 to 360 game days
  (default 90), so a crash costs you less progress.
- **Low-end mode** for older computers: limit the game to 30 FPS and turn off the blur behind panels (both off
  by default).
- **Endless game:** keep playing after the end of the game in 2101. The final screen gets a **Continue game**
  button, and the calendar goes on right away, no reload needed. Based on a mod by **M1lan.**
- **Custom start (NEW GAME):** under the game's start years (2008, 2010, 2014, 2020, 2026) a "Custom start" row
  with a month and a year. The company starts on that date, with research and rivals set between the game's start
  years (May 2017 is 55 % of the way from 2014 to 2020). The latest date is the latest year you reached in any game.
- **Country picker (NEW GAME):** the country cards show tax, start research and the country effects with labels
  instead of the bars without labels, and chips above the list sort the 135 countries (best overall, lowest tax, most
  money, most research, lowest salaries, most sales, A–Z); the first three get a star.
- **Country effects:** the country's cost of production and international trade, only shown in the game, do
  something: a cheap country pays lower salaries (×0.8…×1.2), more trade sells more devices (×0.90…×1.15).
- **Auto continue (NEWS):** a checkbox to the right of the OK button of news. When it is checked, news with a single
  OK closes by itself 3 seconds after its text is typed (1 to 10 seconds in the settings). Dialogs with a choice are
  never closed; unchecking the box or a click in the dialog keeps the open one until you press OK.
- **Real company names:** the other companies are called Sony, Intel, Samsung, … instead of Somy, Infel,
  Samsong, … (game 1.4+), without downloading and loading the names file in the game's editor.
- **Unlimited shares (INVESTING):** the exchange offers as many shares of a company as you can afford, so one
  purchase can go up to the game's own 49 % limit instead of a few percent at a time. Based on a mod by **M1lan.**
- **Stores (MY STORES):** next to the game's **Upgrade all** (one round), **All to max** keeps upgrading every
  store for as long as the money lasts (it asks first and says how much it will spend).
- **Fixed FPS at full speed, above 165:** with a high fixed FPS the game used to run slower (at 240 FPS about 78 %
  of normal speed, at 500 FPS about 37 %), so game 1.6 caps it at 165. With the slowdown fixed, BetterDT lets you go
  higher (Settings → BetterDT → Mods; in practice up to about 200 FPS, the browser's limit).
- **Fair reviews:** the rating of a device comes from all its parts, not from four picked at random. A budget phone
  may have an older camera, a flagship may not; the price is judged by the markup, and a missing feature does not
  count against a cheap device. The reviews show the device's two best and two worst categories (plus Value for
  money and Innovation), and a strip under them shows the score of every category. Works for all 16 device types.
- **Research breakthroughs:** a finished research lab project can research parts before the market has them (up to
  a year early). The device designer then offers the future part, and a device with innovative parts gets better
  reviews and sells more (+10 % per part while the part is new).
- **MY OS UPGRADE** no longer stutters.
- **Laptops with two graphics cards:** the game runs on the faster one.
- A **BetterDT** section in the game settings, where you can turn each of these on or off.
  All texts are in the game's 15 languages.
- **Safe with game updates:** every mod checks at start that the game still has what it needs. A mod that does
  not fit a new game version turns itself off instead of misbehaving, and the settings say why (see
  [Game updates](#game-updates)).

## How to install

1. Download **BetterDT.zip** from the [latest release](https://github.com/JelenXP/BetterDT/releases/latest)
   (under "Assets").
2. Open the game folder: Steam → Library → right-click **Devices Tycoon** → Manage → **Browse local files**.
   A folder with `Devices Tycoon.exe` opens.
3. Open the zip and copy everything in it into that folder: `BetterDT_x64.ext.dll` and the `mods` folder
   must end up right next to `Devices Tycoon.exe`, not in a new subfolder.
4. Start the game. In Settings there is now a **BetterDT** section on the left – that means it works.

**Updates** are automatic: when a new version is out, BetterDT downloads it when the game starts and tells you
in the main menu. Click **Restart now** to use it right away, or **Keep playing** and it starts the next time
you launch the game. You can turn automatic updates off in Settings → BetterDT.

**White screen?** If the game screen ever turns white with a small sad face, BetterDT reloads the game by itself
(you are back in the main menu; load your last save). The main menu then offers **Report problem**, which opens
a prefilled bug report and copies it, so you can also paste it into the Steam discussion.

**Uninstall:** delete `BetterDT_x64.ext.dll` and the `mods` folder from the game folder.

**Problems?** If there is no BetterDT section in the settings, the DLL is not next to `Devices Tycoon.exe`.
Game updates and "Verify integrity of game files" do not remove BetterDT. The file `mods\betterdt.log`
says what happened; please attach it when you [report a problem](https://github.com/JelenXP/BetterDT/issues)
or ask on [Discord](https://discord.gg/JdQEMNNTrN).

## Settings (Settings → BetterDT)

- **General:** BetterDT and game version, automatic updates (on by default), "Check now" (downloads and installs a newer version right away),
  high-performance GPU switch, buttons that open the mods folder, the log, the GitHub releases and the Discord.
- **Mods:** an on/off switch for every mod (with a note when it does not fit the game version) and the mod options:
  - hire-tools: hire everyone found automatically,
  - train-all: mute the click sounds while training,
  - autosave: save every N game days (default 90, 5 to 360; also in the game's own settings),
  - fixed-fps: the FPS used when the game's limit is set to 165 (165 to 360, default 165 = the game's own),
  - low-end: limit to 30 FPS, turn off blur (both off by default; take effect right away),
  - no-ending: skip the final screen and continue right away (off by default),
  - auto-continue: close news with a single OK by itself (off by default; also the checkbox in the news), seconds
    before OK (1 to 10, default 3).

The BetterDT section is in the settings from the main menu and, since game 1.6, also in the settings opened from the
pause menu during a game.

Settings are saved right away into `mods\betterdt.ini`. Turning a mod or the GPU switch on or off takes
effect after restarting the game; the page says so.

The game's own settings are saved right away too: as soon as a control changes something, BetterDT runs the game's
Apply (`applyGameSettings()`), so the game shows "Settings applied" and the Apply button is hidden. A slider is
saved when you let it go. It works from the game's own "unsaved changes" state (`debugGameSettings().dirty`), not
from a list of settings, so settings added by a game update are saved right away as well. If the game no longer has
these functions, the Apply button stays as it is. A mod's control on a game page (the autosave slider) shows
"Saved" there.

## The mods in detail (`mod/mods`)

### `os-perf.js`: smooth OS upgrade cards
The MY OS UPGRADE screen stuttered when clicking quickly. Each of the 35 cards had a `backdrop-filter: blur()`
that does almost nothing visually there, and a double `filter: drop-shadow()` over the whole card. Both were
recomputed on every animation. The mod replaces them with the same shadows drawn once and gives every card
its own layer.
- Look: screenshots differ from the original by 1.4 of 255 levels on average, only on font edges
  (subpixel antialiasing).
- Performance: without the mod the card animations dropped frames. With it the screen holds 105 FPS idle
  and 85 FPS while clicking twice per second, without a single long frame.

### `hire-tools.js`: faster hiring (FIND EMPLOYEES)
- **A second button on every agency** (people icon + number) repeats the search until exactly as many people
  are found as are missing to fill the office for the selected profession.
  - Number = free seats − candidates of this profession already waiting to be hired.
  - The last search is limited so it never finds more people than there are free seats. Example: 6 seats left
    and the searches find 3 + 2, so the third search finds only 1.
  - Every search costs the agency's full price. When the money or the candidates run out, the search stops
    and the game shows its message.
  - At 0 the button is dimmed and a click explains why (office full / enough candidates).
- **AUTO-HIRE checkbox in the top right** (remembered; also in Settings → BetterDT → Mods). When it is checked,
  everyone found is hired right away, after a regular search as well as after the batch search. Candidates of
  the same profession found earlier are hired too while there is room. The result is shown next to the number
  found ("Hired: 2"). Whoever does not fit stays in HIRE EMPLOYEES and the game shows "no free space".

### `train-all.js`: train everyone (UPGRADE EMPLOYEES)
- Game 1.6 has its own **UPGRADE ALL** button in the left panel: one training step for every employee of the
  selected profession, all or nothing. The mod renames it to **UPGRADE DESIGNERS** (the profession as the game
  shows it, so it changes when you switch professions) and puts a second button in the same look under it:
  **ALL TO MAX (N)**, where N is the number of employees of all professions who are not at MAX LEVEL yet. A
  click goes through every profession (the tabs on the left, the shown one first) and all its
  pages and trains until everyone is at the maximum or the money or research points run out; then the profession
  you had open is shown again. To fit both, the game's button is made a little lower. Both buttons appear and
  disappear together, with the game's animation.
- Under the label, like the price on the game's button: about how many research points and how much money it takes
  to get everyone to the maximum (red when you do not have that much). A training step gains 3 to 12 levels at
  random, so it is an estimate with the average gain; in a test it was 818 points and $71.7 million, the training
  took 831 points and $72.5 million.
- Training clicks the game's own buttons on the cards, so the price (sum of the three levels × $1,500 and
  ⌈sum × 0.015⌉ points), gains, salary and perks are computed by the game. The mod only switches pages (`SubPage`)
  and clicks.
- Sounds are muted during the batch (optional), one chime plays at the end. A summary ("Training finished: 29
  upgrades", money and points spent) appears in the game notification. When the money runs out it is appended
  under the game's message.
- Tested in game 1.6: 5 professions, 81 employees, 178 upgrades in 10 s; with 2 research points the game's "not
  enough" message.

### `game-speed.js`: game speed ×2 and ×3
- The game's speed button (`#sbx-speed`) cycles through a fixed list `[1, 1.25, 1.5]`. The mod catches its click
  first (capture listener on the button) and goes to the next of `[1, 1.25, 1.5, 2, 3]` with the game's own
  `setGameSpeed()`, which accepts any speed. So the time scale, the "×2" label and the game's rules (normal speed
  outside gameplay) stay the game's; the mod only adds colours for ×2 and ×3.

### `low-end.js`: low-end mode
- **Limit to 30 FPS:** the game draws at the monitor's refresh rate (vsync) by default, also on static menus where
  nothing moves. The mod sets `runtime.framerateMode = 'fixed'` and `fixedFramerate = 30` at runtime only; the
  game's own FPS setting is not changed. When the game applies its settings again, the mod sets the limit back
  within a second; turning the option off brings the game's setting back. A game setting of a fixed 30 FPS or less
  is kept. Game time does not depend on the frame rate. Measured on the main menu (1440p, vsync 165 Hz):
  CPU 10 % → 2 %, GPU 13 % → 2 %. Office screens already redraw only about 15 times a second, so there it changes little.
- **Turn off blur:** a style rule sets `backdrop-filter: none` on every element. The game's panels stay
  semi-transparent, only without the blur behind them, which weak integrated graphics redo on every frame.
- The game's own **Quality: Low** setting helps only on displays larger than 1920×1080: it then draws
  at 1920×1080 and stretches the picture (about 30 % less GPU work on the main menu at 1440p). On a 1080p or smaller
  display it changes nothing.

### `real-names.js`: real company names
- Game 1.4 can rename companies: **Main menu → Editor → Load file** reads a text file with one name per line
  (line = company id) into `ArrayCompanyNames` (column 0 = the game's name, column 1 = the name shown everywhere).
  The developer publishes such a file with the real names; the mod has the same 469 renames built in.
- The pairs are matched by the game's name (`Somy` → `Sony`), not by the line, so a game update that adds or
  reorders companies does not mix them up. Only cells that still hold the game's name are changed, so a company
  you renamed yourself in the editor keeps your name.
- Only in memory, nothing is written to the game's files. The game loads `Settings.dt` (where the editor keeps the
  names) on the start page, so the mod checks the table every 2 seconds. If fewer than half of the game's names
  are found, the mod turns itself off. Turning it off brings the game's names back after a restart, unless the
  editor saved them in the meantime (its reset buttons undo that).

### `store-upgrade-all.js`: all stores to max (MY STORES)
- The game upgrades the stores of one country at a time: pick the country on the left, then **PAY ALL** (all six
  areas) or the price button of one area. Since game 1.5 its **UPGRADE ALL** button in the top bar does one round
  (PAY ALL once in every country, only when all of it is affordable).
- Right next to it, in the same look (the game's button moves a little to the left to make room), **All to max**
  clicks PAY ALL in every country, round after round, while the money lasts; when no full round is affordable any
  more, the cheapest single areas are bought with the rest. A click first asks: a dry run of the same rounds (with
  the game's price formula and random gains) shows about how much money it will spend and the store levels after
  it. The button shows the progress, a click on it stops, and at the end the game's message says how many upgrades
  were bought for how much. It hides itself if it would cover the money in the top bar.
- Every upgrade is a click on the game's own PAY ALL or area button (the same as with the mouse), so the price
  check, paying, the random gains, the store level and the demand are the game's code. The mod only picks the
  country (`MiniPage`, as a click on the country does), clicks, and opens the country you had open again at the end.
  Before every click it computes the price with the game's formula (`ArrayShops` base price × (5 + √ average
  quality) / 100 × stores, −10 % with the perk); when the game takes a different amount, the mod stops and turns
  itself off. Sounds are muted during the batch and one plays at the end.
- Tested in game 1.6: from $15.4 billion "to the max" bought 26 161 upgrades and left less than the cheapest next
  upgrade.

### `unlimited-shares.js`: unlimited shares (INVESTING)
Based on the "unlimited shares" mod by **M1lan.** – thank you!
- **How the game sells shares:** on a company's page the **Buy** tab offers only what the exchange has on offer
  (`ArrayInvesting` row 8). The game refills it by 2.5–3.5 % of all shares when it drops below 2.5 %
  (`investingUpdate`), so reaching the game's limit of 49 % (above it a company can only be bought in talks) takes
  many purchases over many days.
- **What the mod does:** when you open a company or its Buy tab, and after a purchase, the offer of that company is
  raised to as many shares as your money buys (price × 1.025 commission, taken from the game's own quote). The
  slider and the texts are then set up again with the game's own `investingSyncSlider` and `InvestingStock_Text`.
- **Unchanged:** the purchase itself is the game's (`investingBuy`): the slider, the price, the 49 % limit and the
  "not enough funds" check. When you leave the company or the screen, its offer goes back to what the game offered,
  minus the shares you have bought, so the save keeps the game's own numbers.
- Changes from the original: it acts only on the company you have open (not on every company in every frame),
  takes the commission from the game instead of a fixed factor, does not touch the sell side (row 9 is how many
  shares the company buys back, not a buy offer), and checks at start that the game still reads the offer the same
  way.
- Tested in game 1.4: a company with 4 005 506 shares on offer showed 66 859 684 on the slider, the game's 49 %
  limit; buying all of them cost exactly the quoted price, and after leaving the page the offer was 0.

### `fixed-fps.js`: fixed FPS at full speed, above 165
- **The problem:** in Construct's "fixed" frame rate mode every tick moves the game time by exactly 1 / FPS, no
  matter how much time really passed. The ticks are timed with `setTimeout`, and the browser does not run them much
  faster than about 190 per second. So above that the game time falls behind: measured in game 1.4, fixed 60 and
  144 FPS run at full speed, 240 FPS at 78 % and 500 FPS at 37 % (the calendar too: 4 days instead of 10).
- **The fix:** in fixed mode the runtime measures the real time between ticks, exactly as in the default vsync mode
  (same limits). The ticks are still paced at the chosen FPS, and when the computer keeps up nothing changes.
  Technically `C3.Runtime.prototype._MeasureDt` is wrapped, and during that call only `GetFramerateMode()` answers
  "vsync". If the runtime's code changes, the mod does not start.
- **Above 165:** game 1.6 works around the slowdown by capping the fixed FPS at 165 (its list of limits ends there,
  and every second it sets anything higher back). With the slowdown fixed, the mod allows more: when the game's limit
  is 165, the runtime runs at the FPS from Settings → BetterDT → Mods (165 to 360). The runtime's `fixedFramerate`
  reads at most 165 for the game, so its cap leaves the value alone. Tested in game 1.6: asked for 360, it ran at
  199 ticks per second (the browser's limit) with the game time at exactly 1.00× real time.

### `no-ending.js`: endless game
Based on the "prevent retirement" mod by **M1lan.** – thank you!
- **How the game ends:** on game day 34000 (early 2101) the event sheet calls `triggerEndGame()`. It sets the
  global `class` to `"END GAME"` and shows the final summary, whose only button goes to the main menu. The date
  engine only runs while `class` is `"GAMEPLAY"`, so a game kept open behind the screen has a frozen calendar.
- **Continue game** (the game's own text, so in every language) is added under the game's button. It calls the
  game's `resetEndGame()` and sets `class` back to `"GAMEPLAY"`: the calendar runs on in the same session.
  The game only ends on that one day, so the screen does not come back. The "game finished" achievement still
  counts, as the game checks it before the screen is shown.
- **Skip the final screen** (option, off by default) continues right away without the summary.
- A game stuck in `"END GAME"` without the screen (e.g. after a mod that only removed the screen) is put back to
  `"GAMEPLAY"` after 3 seconds.

### `custom-start.js`: custom start (NEW GAME)
- The game's start years are presets. When a new game loads, `Loading_NewGame_2` (event sheet LOADING GAME)
  compares `Year` exactly with 2008, 2010, 2014, 2020 and 2026 and then sets the date and copies one column of
  `ArrayMyResearch_NewGame.json` (the start level of each of the 800 research items, one column per start year)
  into `ArrayMyResearch`. Nothing else in the game depends on the start year: money, office, employees and bank
  are the same. The rivals (`ArrayRatings/ArrayRatingsCompanies.json`) have one layer per start year (earnings,
  price, fans…); at the first game day the game keeps the layer of the start year. New product lines and parts
  come by game day (`DictionaryTimeline.json`, e.g. smartwatches on day 2549, December 2014), for any date.
- Under the start year cards a "Custom start" row in the game's look: month and year with arrows, how far the date
  is between two start years ("2014 → 2020: 55 %") and the next product line that comes later ("Next:
  Smartwatches 12/2014"). Selecting it selects the game's card of the start year at or before the date (the
  company is built on it); a click on a game card turns the custom start off. The chosen date is remembered.
- While that new game loads, the game's requests (XHR) for the two files get changed copies: that start year's
  column and layer are moved toward the next start year by that share (research rounded to whole levels).
  When the game asks for `DictionaryTimeline.json`, right after setting its start date, `Year`, `Month`, `Day`,
  `DayTotal` and `DayInMonth` get the chosen date, so the game's timeline check that follows counts from it.
- The latest date is December of the latest year reached in any game (the game's own rule for its start years),
  at most December 2026. `getCampaignStart()` counts from the first month of the game. The stats page counts
  its days with the game's internal copy, so for a start late in a year it shows up to 11 months more.
- Tested in game 1.6: start in May 2017 = date 1. 5. 2017 (game day 3406), research between the 2014 and 2020
  columns as computed (e.g. 11 → 18 gives 15), rivals between the two layers; a normal 2014 start unchanged.

### `country-effects.js`: country effects
- What a country (`ArrayCountries`: name, budget, tax, cost of production, international trade, research level)
  does in game 1.6: the budget is the start money, the research level the start research points, the tax rate is
  used every month (`applyMonthlyTaxes`, on the profit, scaled by the revenue). Cost of production and trade are
  only shown: the salary module has a scale of the salaries by cost of production (`getSalaryConfig().COUNTRY_SCALE`,
  ×0.6…×1.4) that is turned off, and trade only spreads the sales over the countries on the stats page. Checked
  in the code (every read of the array and of `CompanyCountryID`) and in the game (reads logged while playing).
- Cost of production: the mod turns the game's salary scale on with a milder range, ×0.8 at 1 % … ×1.2 at 100 %
  (`setSalaryConfig`). The monthly payment (`applySalaryExpences` → `SalaryExpences`) uses it; the salaries shown on
  the employees stay the game's own.
- International trade: the potential of a device is `(AUDIENCE_SEED + fans × AUDIENCE_FAN_W …) × …` and the daily
  sales are a share of it, so both multiplied by ×0.90 at 0 % … ×1.15 at 100 % (`setDeviceSalesConfig`) make the sales
  (and the game's recommended batch size) that much higher, for the country in `CompanyCountryID`.
- The cost of the devices is left alone: the game also judges the price against it (demand) and uses it for
  restocking, so a lower cost would make every device look overpriced.
- Turned off, the game's own values are back. Tested in game 1.6: Czech Republic (cost of production 78 %, trade
  84 %) pays 7 176 319 instead of 6 458 687 a month (×1.111), sales ×1.11; turned off 6 458 687 again.

### `country-picker.js`: country picker (NEW GAME)
- The game's picker (`initCountryPicker`) shows flag, name, start money and four bars without labels. Every card
  gets tax, research and, with `country-effects.js` running, salaries and sales against the game's own (green is
  better); without it cost of production and trade say "no effect".
- Chips under the search sort the cards with CSS `order` (the game's cards, search and selection stay as they are):
  best overall, lowest tax, most money, most research, lowest salaries, most sales, A–Z. The first three of the sort
  get a star; the sort is remembered. "Best overall" weighs the tax most (35 %, paid the whole game), then start
  money 20 %, research, salaries and sales 15 % each, each scaled between the lowest and the highest country.
- The cards come in one by one as in the game (`--i`, 45 ms apart, the 16th and later together), in the sorted
  order: until a card is sorted its entrance waits hidden (`animation-play-state: paused`), and a new sort plays it
  again.

### `auto-continue.js`: auto continue (NEWS)
- The game shows news, warnings and tips in one HTML dialog (`showOfficeNews`) with no button, one OK, or two
  buttons for a choice; with one button it has the class `on-single`. The text is typed letter by letter.
- To the right of OK (positioned absolutely, so the game's button stays exactly in the middle) a checkbox
  **Auto continue** in the look of the dialog, remembered in the BetterDT settings. When it is checked, a dialog with
  a single button closes 3 seconds (1–10, Settings → BetterDT → Mods) after the game has typed the whole text, by a
  click on the game's own OK, so the game does what OK does (an award ceremony starts, for example). A small ring
  next to the checkbox fills up meanwhile; OK can be pressed any time.
- Never closed: dialogs with two buttons (a choice, e.g. "Later" / "Pay bonuses to all employees") or without
  buttons. Unchecking the box stops the countdown of the open dialog too, and so does a click anywhere else in the
  dialog (to read it in peace): it then waits for OK. Checking the box again starts the countdown from the beginning.
- Tested in game 1.6 on the game's own news: closed 3.0 s after the text was typed; a click in the dialog and
  unchecking kept it open; a two-button dialog had no checkbox.

### `autosave.js`: adjustable autosave
- The game autosaves every 30, 60, 90, 180 or 365 game days, or never (Settings → General → Autosave). It calls
  `globalThis.tickAutoSave()` once per game day; the mod replaces it with the same logic and its own interval:
  any number of days from 5 to 360 in steps of 5 (default 90).
- The game's Autosave row becomes a slider in the game's own look, saved right away (the same option is in
  Settings → BetterDT → Mods). With the mod turned off, the game's own row and interval are back.
- The save itself is the game's own: `debugAutoSave()` runs the game's autosave (SaveGame with its backup and
  read-back check), which skips saving outside gameplay, while paused, while a save is in progress, and on the
  bankruptcy and end-game screens. The mod then tries again the next day.
- Like the game, it counts from the day a game is started or loaded.
- Tested on a copy with file writes blocked: with the interval set to 30, it saved every 30 days over 700 game days.

### `research-all.js`: Research all
- **The game's button (game 1.4+):** **Research all** in the top bar of the research page researches only the tab
  you have open on the left (and, when a category is picked in the top bar, only its cards), recommended functions
  first, with all research points but at most half of the money (`planResearchAll`), so often only a part. It asks
  first with the levels, functions and cost. The mod renames it to **Research tab** so the two are told apart.
- **Ours:** **Research all** right next to it, styled with a copy of the CSS of the game's button: everything still
  open on all tabs, the game's own list for its sandbox button (`debugResearchAllTargets()`). In sandbox mode, where
  the game's button is free and researches everything, the mod stays off.
- Price = remaining levels × price per level (`ArrayResearch` columns 1 and 2, the same the cards show). The button
  gets the game's grey `rc-all-empty` look and ignores clicks when nothing is left or the points or money are not
  enough for all of it. A click first opens a confirmation with the price and the number of levels
  (`BetterDTUI.dialog`, the BetterDT dialog that other mods can use too).
- Every level is a click on the research card, so the game checks the price, deducts the tax, pays and raises
  the level itself (the card click reaches the game's `research-buy-signal` event synchronously). Other tabs are
  opened like a click on them does (`MiniPage`, `Research_ButtonsOpacity`, `ResearchPage`), and the tab you had open
  comes back at the end. Sounds are muted during the batch (one plays at the end); if the game rejects a click,
  the mod stops. Functions that only become available after others are researched are left for the next click.

### `fair-reviews.js`: fair reviews
- The game's review function for the device type (`ReviewsEngine_<Type>`, 16 of them) pushes one entry per aspect
  (camera, screen, price, …) into `ArrayReviews_Temp`, then `ReviewsEngineResults` picks 4 of them at random,
  each with a random score from its range, and the stored rating is the mean of those 4. The mod keeps the game's
  run and, after it, scores every pushed aspect:
  - a part the game compares with the newest one on the market by how many generations it is behind, on a scale
    that depends on the device's price class (budget, mid, flagship: the price against the flagship cost of that type
    in that year, `simulateDeviceCost`); a part from the future scores like the newest one;
  - the price by the markup over the production cost, with limits that move with the class and the number of
    innovative parts;
  - a missing feature (a yes/no aspect) is not counted for a budget device; other aspects keep the game's range;
  - two more categories: Value for money (quality of the parts against the price) and Innovation (parts born after
    today).
- The aspects are grouped into categories (display, camera, performance, …). The 4 reviews are the two best and two
  worst categories, with the game's own review texts for that score and the game's closing sentence; an overpriced
  device always shows Price among the worst. The final rating is the mean of 4 reviewers, each weighing every
  category a bit differently (the shown ones, the price and the device's strong points more); while the game
  stores the rating, all 4 scores hold it.
- Under the reviews a strip shows every category with its score as stars, the 4 shown ones framed.
- The aspect table (`lib-review-data.js`) is generated from the game's data by `tools/gen-review-data.mjs`, so a
  game update is checked by generating it again. The math is in `lib-review-core.js`, the texts the game does not
  have (Value for money, Innovation, the strip) in `lib-review-texts.js`, in the game's 15 languages.
- Turned off, the game's own random reviews are back; ratings already stored stay.

### `research-breakthroughs.js`: research breakthroughs
- A research lab project runs 30 days and fills the lab's point pool. When it ends, the pool decides how many
  breakthroughs it gives: the first comes with a chance of about 47 % at 750 points, a second and third only after
  the first, and more points give more (`lib-breakthrough-core.js`).
- A breakthrough raises one research category one level ahead of the parts on the market: the next part of that
  category, normally available up to a year later. A category you are more than a few levels behind in cannot get
  one. Categories of the device types you released in the last two years are drawn three times as often. The
  game's own news window (on the next day in the office) names the parts and the day they would normally come out;
  the game waits while it is open, as for its other news.
- The device designer lists a category's parts up to the number already on the market (it counts them into
  `ArrayFunctionsOpened`); for a category researched ahead the mod raises that count to the research level, so the
  future part is offered and unlocked.
- Sales: a device whose parts were not on the market at its release sells more. While the game computes the daily
  sales (`tickDeviceSales`), its popularity counts 10 % more per innovative part (20 % for two, then less per
  part), fading out within 60 days after the part reached the market; the popularity it keeps is the game's own.
- Tested in game 1.6: a project with 732 points gave one breakthrough and the dialog; the laptop designer offered
  the future screen resolution; with a 30 % bonus a device sold 1.30× the units with the same popularity left.
- Turned off: no new breakthroughs and no sales bonus; levels already researched stay, but the designer offers only
  the parts on the market again.

All buttons use the game's own look (its HTML buttons' CSS, or its canvas buttons, gradients, icons and font).

### Game updates
Mods use the game's own functions, objects and tables, which a game update can rename or change. So every mod
is registered through `BetterDTKit` (in `betterdt-settings.js`) with a list of what it needs:

- **Before start** (when the game reaches the main menu): global functions, object types, global variables and
  game texts. Texts are listed with their English wording; if an update moves a text to another index, it is
  found again by that wording. A mod with something missing is not started.
- **After a saved game is loaded** (the company tables are empty in the menu): table sizes and checks of what the
  columns hold (e.g. the profession in `ArrayEmployees`). A mod that fails them is stopped.
- **Objects on a screen** are listed by their uid in game 1.3.0 with type, layer, size and position. If the uid
  no longer fits (wrong type, layer or size), the object of that type and layer with that size nearest to the old
  position is used instead, and the settings note it.
- **While running:** errors in a mod's timers and listeners are counted; after 20 the mod is stopped and cleaned
  up (`dispose`). Mods also check their own results: `research-all` stops when the price paid differs from the
  computed one, `autosave` gives the game
  its own autosave back when the game stops calling `tickAutoSave()`, `hire-tools` charges the price shown on the
  agency card, and `game-speed` steps aside when the game itself styles ×2 / ×3.

What it shows the player:
- **Settings → BetterDT → Mods:** under a mod that does not fit, "Does not fit this game version, turned off" or
  "Stopped after repeated errors", with the details; "Works, but something in the game has changed" when an object
  or text had to be found again.
- **Settings → BetterDT → General:** the game version.
- After the game itself was updated, a dialog in the main menu: "Devices Tycoon 1.3.0 → 1.3.1. BetterDT has checked
  its mods", with the mods that were turned off.
- If an update changes the game's settings page so that the BetterDT section cannot be added, a **BetterDT** button
  in the corner of the settings screen opens the mods as a plain on/off list.
- Crash reports include the game version and the mods that are not running.

### Writing your own mod

Put a `.js` file into `mods` and add it to `mods\mods.json`:

```js
BetterDTKit.mod('my-mod', {
  needs: { functions: ['setGameSpeed'], objects: ['ArrayOffices'], vars: ['Budget'], arrays: { ArrayOffices: [5, 1] } },
  texts: { 10974: "You don't have enough funds" },
}, (runtime, kit) => {
  runtime.globalVars.Budget;                       // global variables from the event sheets
  runtime.objects.ArrayOffices.getFirstInstance(); // arrays, dictionaries, sprites…
  const tick = kit.guard(() => {});                // errors are counted, 20 stop the mod
  runtime.addEventListener('tick', tick);          // every frame
  kit.text(10974);                                 // a game text in the player's language
  BetterDT.settings.bool('my-mod.option', true);   // settings from betterdt.ini
  return () => runtime.removeEventListener('tick', tick);   // dispose
});
```

`BetterDT.register('my-mod', runtime => { … })` still works for a mod without checks.

`DTMods` is an alias of `BetterDT` for older mods. `examples/mods` has two development helpers:
`example.js` and `probe.js` (with `probe-server.mjs` it sends the runtime state to `http://127.0.0.1:9334`).

## How the loader works (`loader/`)

- `WV2ExtManager.dll` from the Construct wrapper loads every `*.ext.dll` in the game folder and calls its
  `WrapperExtInit` (that is how `Steam_x64.ext.dll` is loaded). BetterDT returns an object with empty methods
  and registers no component.
- On load it redirects `GetProcAddress` in the exe's import table. The exe gets
  `CreateWebViewEnvironmentWithOptionsInternal` through it, so the loader sees the environment options and adds
  `--force_high_performance_gpu`. The switch does not pick a vendor: Chromium asks Windows (DXGI) for the
  "high performance" adapter, the same order the Windows graphics settings use:
  - integrated graphics only: stays on it,
  - integrated + dedicated (NVIDIA, AMD, Intel Arc): moves to the dedicated one,
  - desktop with a dedicated GPU only: no change.

  On a laptop with Intel UHD and RTX 5070 the menu went from 84–88 % GPU load and 70–80 FPS (Intel)
  to 8 % and ~130 FPS (RTX).
- After the controller is created (all four creation methods are hooked) the loader registers
  `AddScriptToExecuteOnDocumentCreated` with a script built from `mods\mods.json` and the files in `mods\`.
  The script runs only in the main page on `app.localhost`.
- `https://betterdt.localhost/…` is served through `WebResourceRequested` (registered after the game's own
  handler, which would otherwise overwrite the response). The settings page uses it for `state`, `set`,
  `check`, `install` and `open`. Only requests from the game page are accepted.
- **Updates:** `github.com/JelenXP/BetterDT/releases/latest` redirects to `…/tag/v<version>`, which tells the
  loader the latest version without downloading anything. When it is newer, the loader downloads
  `BetterDT-update.zip` (a copy of `BetterDT.zip`, the zip players install by hand, so GitHub counts updates and
  manual downloads apart; `BetterDT.zip` when a release has no copy), checks the CRC-32 of every file and the
  version in `mods/betterdt-version.txt`, and only then replaces the files. The loaded DLL is renamed to
  `BetterDT_x64.old` and deleted on the next start; the new version is used after a restart.
  `mods\mods.json` keeps any mods you added yourself. Official mods that a game update made redundant
  (`vacation-tools.js`, `update-all.js`, `os-upgrade-all.js` since game 1.5/1.6) are skipped and their files deleted
  when the game starts. The zip is uncompressed so the loader can read it
  without an inflate library. `mods/betterdt-version.txt`:

  ```
  betterdt-manifest 2
  version 0.3.2
  change 0.3.2 <release notes line>     (the whole history from loader/CHANGES.txt, newest first)
  note <release notes line>             (for BetterDT up to 0.3.1, which only reads these)
  mods betterdt-settings.js os-perf.js hire-tools.js train-all.js autosave.js
  ```
  The new-version dialog lists the notes of every version newer than the installed one (at most 12 lines).
- **Restart:** "Restart now" starts the exe again with `BETTERDT_WAIT_PID` set (the environment Steam gave the
  game is inherited) and closes the game window. The new instance waits in the hooked environment creation until
  the old process and its WebView2 browser process have exited, because it needs their browser profile.
  Downloaded files are replaced only after the running game has read its mods, so a session never mixes versions.
- **Crashes:** the loader handles WebView2's `ProcessFailed`. When the page process dies (Chromium's white page
  with a sad face), it logs the kind, reason, exit code and free memory, reloads the page (at most 3 times in
  10 minutes) and keeps the details in `mods\betterdt-crash.txt`. When the browser process itself dies, it
  restarts the game. The settings mod reports what the game is doing every 15 s (screen, game day, JS heap), so
  the crash dialog's "Report problem" can open a prefilled GitHub issue with that and the system (Windows, CPU,
  RAM, GPUs with driver versions, WebView2 version) and copy it to the clipboard. Nothing is sent automatically.
- Everything it does is written to `mods\betterdt.log`.

**Build:** `loader\build.bat` (Visual Studio 2022 with C++; the WebView2 header is downloaded from NuGet),
then add the release notes to `loader\CHANGES.txt` and run `loader\package.ps1`, which creates
`loader\dist\BetterDT.zip` and its copy `BetterDT-update.zip`.
Publish: `gh release create v<version> loader/dist/BetterDT.zip loader/dist/BetterDT-update.zip`.

## How the game is built

- **Engine:** Construct 3 (Scirra), an HTML5/JavaScript export in a **WebView2** wrapper
  (`Devices Tycoon.exe` + `*.ext.dll`). It is not Unity.
- **Everything is in `www/assets.dat`** (1.4 GB, 9,362 files): a simple uncompressed Construct bundle
  (`c3ab` / `fdir` / `blob`).
- **Game logic** = Construct event sheets in `data.json` (50 MB, 299 layouts, 287 event sheets,
  10,519 object types) plus the author's own JS (saving, perks, achievements…) in `scripts/c3main.js`.
- **Game data** = about 600 JSON files in the Construct Array format: processors, GPUs, OSes, offices,
  marketing, awards, translations…

The author built an **[Integrity] check** into the game: it reads `package.json` and quits the game
("Game files have been modified") when `enable-devtools` is on or `chromium-args` contains
`--remote-debugging-*`. The author does not want DevTools in the game and BetterDT leaves that alone:
it never enables DevTools or remote debugging.

## `dtmod.mjs` (Node 18+, no dependencies)

The older approach: repack `assets.dat` with the mods inside. BetterDT does not need it.

```bash
node dtmod.mjs list "D:\SteamLibrary\steamapps\common\Devices Tycoon\www\assets.dat" ArrayProcessors
```

```bash
node dtmod.mjs unpack "D:\SteamLibrary\steamapps\common\Devices Tycoon\www\assets.dat" extracted "\.json$"
```

A mod is a folder whose files have the same paths as in the bundle. A file with the same name replaces the
original, a new one is added. `install` creates the backup `assets.dat.orig` the first time and always packs
from it, so mods never stack. A small `dtmod.json` marker in the repacked bundle lets `install` notice that
Steam installed a new game version (it becomes the new backup). `restore` puts the original back.

```bash
node dtmod.mjs install "D:\SteamLibrary\steamapps\common\Devices Tycoon" mod
```

```bash
node dtmod.mjs restore "D:\SteamLibrary\steamapps\common\Devices Tycoon"
```

`node dtmod.mjs gpu <game folder> [on|off]` adds the high-performance GPU switch to `package.json` instead.

## Notes

- A Steam update or "Verify integrity of game files" does not touch BetterDT (it only adds files).
- Tested on game versions 1.3 (build 26033576) and 1.4.
- Changing logic in `data.json` is possible but hard (a compiled, positional structure without names).
  JS mods and the data JSON files are the practical way.
